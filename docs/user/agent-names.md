# Agent names

*Why somebody is called `Chen Palette-Tidier`, and why their surname keeps changing.*

<img src="../images/panels/agents-roster.png" width="256" alt="The agents panel listing agents by full name — a first name and a job-derived surname — each with a status dot and the job they are on.">

*Four sessions, four names. The surnames come from what each one is actually doing.*

A terminal tab is a person, so the office gives it a person's name. It is one of the
quieter pleasures of watching the room: you stop thinking of them as sessions within about
a minute.

A terminal tab is a person, so it gets a person's name — `Chen Palette-Tidier` — in two
halves:

- **First name** is derived from the session, never random, so the same tab is the same
  colleague across a reload, an office switch and a replay. It never changes, and two tabs
  in one room never share one.
- **Surname is the job**, and it moves with the work: a noun and a verb welded into
  something a person could plausibly be called. Before the first prompt it comes from the
  git branch; after that, every new job earns a new one, because a colleague whose name
  still describes last week is worse than no name at all.

| The job in hand | Becomes |
| --- | --- |
| "Research how cats sleep" | `Cat-Researcher` |
| "Bake some sourdough bread" | `Sourdough-Baker` |
| "Refactor the palette code" | `Palette-Tidier` |
| "Fix the nav grid around the couch" | `Nav-Mender` |
| "Look at the naming protocol" | `Naming-Reader` |

Verbs map to jobs — *fix* → Mender, *investigate* → Sleuth, *write* → Scribe, *optimise* →
Tuner, *deploy* → Shipper — in every form people type them, so "shipping the globe" is a
Shipper too.

**A surname is never technical.** Identifiers, paths, flags, versions and acronyms are
struck out before a noun is chosen, so nobody is called `AopSource-Builder` or
`SSE-Mender`. If a job is jargon all the way down the name falls back to the bare job —
`Chen Mender` — which is a real surname and an honest one. Adverbs go the same way: "grow
the plants faster" is about plants, and `Faster-Gardener` is a name about nothing.

Two brakes stop this becoming a flicker. Only a whole instruction — a verb and something
plain for it to act on — earns a new surname, so "yes, carry on" leaves the name alone.
And a name is only double-barrelled if it fits the pill: `Shan Sourdough-Bak…` has lost
the word that made it a person, so it is `Shan Baker` instead.

Under the default redaction no prompt ever arrives, so the branch-derived surname simply
stays. The naming can only ever use something the office was already told.

## Where you see them

Above their head on the floating name tag, in the agents roster (`A`), and at the top of
the detail panel when you click somebody. First names only in the narrow places — a
surname earns nothing in a two-inch row.

Every source is named this way, [Test Data](sources/test-data.md) included, so the default
office demonstrates the naming rather than opting out of it. Telling a simulated agent from
a real one is the job of the mark each one wears, not of the name.

**OpenClaw is the exception**, because its agents have already told you who they are — see
[names, colours and faces](sources/openclaw-identity.md).
